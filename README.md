# رقميات — كتالوج قطع الموبايلات الخاص

واجهة عربية متجاوبة للهواتف والكمبيوتر، مع خادم خلفي وقاعدة بيانات SQLite، وصلاحيات مدير/موظف، وسجل تدقيق. **لا يعرض الموقع أسعاراً ولا يحتوي على حقل سعر في لوحة الإدارة.**

## مهم: GitHub Pages لا يشغّل الخادم
هذا المشروع يستخدم Node.js وExpress وقاعدة بيانات SQLite وتسجيل دخول. لذلك لا يكفي رفعه إلى GitHub Pages وحده؛ Pages يستضيف ملفات ثابتة فقط ولا يشغّل `server.js` أو قاعدة البيانات. استخدم GitHub كمستودع للكود، وانشر التطبيق على استضافة تدعم Node.js وتخزيناً دائماً. لا ترفع `.env` أو قاعدة البيانات أو كلمات المرور إلى GitHub.

## التشغيل محلياً
المتطلبات: Node.js 20 أو أحدث.

1. انسخ `.env.example` إلى `.env`.
2. عيّن قيمة عشوائية قوية وفريدة لـ `SESSION_SECRET` (32 حرفاً أو أكثر).
3. من مجلد المشروع نفّذ:
   ```bash
   npm install
   npm run create-admin
   npm start
   ```
4. افتح `http://localhost:3000`.
5. ينشئ أمر `create-admin` حساب المدير الأول؛ لا توجد بيانات دخول افتراضية.

## الرفع إلى GitHub
1. أنشئ مستودعاً جديداً على GitHub.
2. ارفع ملفات المشروع ومجلد `public/` و`server.js` و`package.json` و`README.md`.
3. لا ترفع `node_modules/` أو `.env` أو `data/` أو ملفات SQLite.
4. اربط المستودع بخدمة استضافة Node.js.
5. أضف `SESSION_SECRET` و`NODE_ENV=production` إلى متغيرات البيئة في إعدادات الاستضافة.
6. تأكد أن الاستضافة توفر تخزيناً دائماً لقاعدة SQLite. إذا كانت المنصة تستخدم نظام ملفات مؤقتاً أو عدة نسخ للتطبيق، استخدم قاعدة بيانات دائمة مناسبة ومخزن جلسات مركزي.
7. أنشئ حساب المدير على الخادم من الطرفية مرة واحدة باستخدام `npm run create-admin`، أو نفّذ إجراء إنشاء المدير الآمن الذي يناسب منصة الاستضافة.

## الحماية
- المدير وحده ينشئ حسابات المستخدمين ويستطيع تفعيلها أو إيقافها.
- كلمات المرور تحفظ بصيغة bcrypt hash.
- جلسات HttpOnly وSameSite=Strict، وSecure في وضع الإنتاج.
- حماية CSRF وتحديد محاولات تسجيل الدخول وHelmet وسجل تدقيق.
- استخدم HTTPS، ولا تضع مفاتيح المورد أو أسرار الجلسات في ملفات الواجهة أو في GitHub.
- هذه بنية تطبيق أولية؛ اختبر إعدادات الاستضافة والنسخ الاحتياطية والصلاحيات قبل استخدام بيانات محل حساسة.

## كتالوج المورد والتوافق
لا يوجد تكامل مورد فعلي مفعّل افتراضياً، لأن اسم المورد وتوثيق API غير متوفرين. توجد نقطة ربط اختيارية تحتاج مطابقة عقد API الحقيقي للمورد قبل استخدامها. لا توجد منتجات معتمدة مسبقاً على أنها متوافقة 100%.
- `unverified`: التوافق غير متحقق منه.
- `verified`: يتطلب رقم القطعة ورابط مصدر واسم الشخص الذي تحقق.
- يجب مطابقة رقم طراز الهاتف الدقيق ورقم القطعة/الفلاتة مع مصدر المورد قبل اعتبار التوافق مؤكداً.
